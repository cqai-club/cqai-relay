## 板块 2 · 为什么需要 Relay（问题 → 解决）

**板块标题**
> 模型和应用都在变多，瓶颈出在"中间的管理"

**左列 · 现实问题**
- 接一个新模型就要改一遍应用代码，重复开发、难以维护；
- 文本、图像、视频、语音能力繁杂，调用口径不统一；
- 每个应用能用哪些模型、额度多少、成本多少，没有统一策略；
- 供应商故障、限流时没有兜底，应用可用性难以保障。

**右列 · Relay 给出的答案**
- 模型一次接入，应用永远只面对同一套统一接口；
- 策略与模型解耦：换模型、扩模型，不碰业务代码；
- 每个应用独立配置：可用模型 / 限流 / 配额 / 计费，一目了然；
- 多供应商互为备份、自动容灾，调用连续可用。

**一句话收束**
> 接入、路由、治理、计量由 Relay 统一完成，应用团队只关心业务本身。

## 板块 4 · 应用接入与策略配置（核心差异化）

**板块标题**
> 模型是资源，策略才是配置——每个应用都有自己的 AI 规则

**引言**
> 在 Relay 上，每个 AI 应用都是一个独立接入方：它声明自己需要哪些模型与 AI 服务，平台按「应用 + 策略」统一供给与治理。

**三步了解它（流程条）**
1. 注册应用：为每个 AI 应用创建独立接入身份；
2. 配置策略：指定可用模型与 AI 服务，绑定路由、限流、配额、计费规则；
3. 统一调用：应用经由统一网关接入，全链路可观测。

**策略矩阵（六张能力卡）**

| 策略能力 | 一句话描述 |
|---|---|
| 模型路由 | 按应用限定可用模型；多供应商按权重 / 优先级分发，自动容灾切换 |
| 访问安全 | 应用级凭证、权限分组、密钥管理、调用来源管控 |
| 限流配额 | 应用 / 分组级并发与速率限制、额度上限、超额保护 |
| 计量计费 | 按模型单价与倍率自动核算，成本精准分摊到每个应用 |
| 监控告警 | 调用量、时延、成功率、失败原因实时可视，异常及时告警 |
| 日志审计 | 全链路调用日志，问题可定位、消耗可追溯 |

## 板块 8 · 为什么选择 Relay

- **面向应用的治理视角**：不是发一把裸 API Key，而是以应用为中心的策略管理；
- **国产模型优先**：围绕国内主流模型生态持续适配，名单不断扩充；
- **统一协议、低成本接入**：OpenAI 兼容接口，已有应用平滑迁移；
- **可观测、可计量**：调用、成本、日志全链路透明，支撑分摊与审计；
- **私有化可部署**：支持企业私有化环境，满足数据安全与合规要求（按实际能力表述）；
- **自用验证**：自家多款 AI 产品长期运行其上。
